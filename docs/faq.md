# FAQ

Короткие ответы на частые вопросы. Если ищешь решение конкретной проблемы — см. [troubleshooting.md](troubleshooting.md).

## Общее

### Зачем нужен gofer, если есть LSP?

LSP — это навигация на уровне одного файла/позиции, требующая запущенного language server. gofer добавляет принципиально другое:

- Семантический поиск по индексу (то, что LSP не умеет в принципе).
- Token-эффективные read-операции (`skeleton`, `read_function_context`, `read_types_only`).
- Граф вызовов и символов поверх SQLite — быстро, без LSP.
- Batch-запросы и серверный кеш.
- Язык-агностичность: один сервер обслуживает Rust + TypeScript + Vue + Python в монорепо без LSP-серверов.

gofer не содержит LSP-инструментов. Если нужна LSP-навигация — используй встроенные средства IDE или MCP-сервер на базе rust-analyzer/pyright напрямую.

### Зачем нужен gofer, если есть ripgrep?

ripgrep отличный для регулярок по тексту. Но:

- Не знает синтаксиса — `grep -n 'fn foo'` найдёт и определение, и вызов, и комментарий.
- Не понимает, какие файлы важны для задачи (`smart_file_selection`).
- Не умеет семантику — «найди код про auth» не отвечает.
- Не строит граф вызовов — `get_callers`/`get_callees` это даром.

В типичной интеграции у MCP-клиента есть **оба** — ripgrep для точных строк, gofer для семантики и структуры.

### Чем отличается от Sourcegraph / Cody?

Sourcegraph — сервис, рассчитанный на индексацию репозиториев целыми командами, с веб-UI, шарингом, GraphQL API. gofer — локальный сервис для одного разработчика, без UI, оптимизированный под MCP-clients и одну машину.

### Почему MCP, а не REST?

MCP — стандарт для интеграции LLM-агентов. Поддерживается Claude Code, Qoder, Cursor, Continue. REST API не реализован и сейчас не планируется, но JSON-RPC поверх Unix-сокета — фактически тонкий слой, который можно дёргать любым клиентом, говорящим JSON-RPC 2.0.

## Установка и настройка

### Зачем внешний эмбеддер? Не проще ли локально?

Раньше было локально (BGE-Small через ort/onnxruntime). Отказались, потому что:

- Бинарь раздувался до >100 МБ.
- ONNX/ort зависимости тащили нативные библиотеки, плохо переносимые между ОС.
- На CPU локальная модель работает медленнее, чем централизованный HTTP-сервис с батчингом.
- Сменить модель означало пересобрать gofer.

Сейчас разделение чище: gofer индексирует, HTTP-сервис эмбеддит. См. [embedder.md](embedder.md).

### Какую модель эмбеддера выбрать?

Для большинства задач код-поиска:

- **`nomic-embed-text-v1.5`** (768 dim) — баланс качества и скорости, хорошо на коде.
- **`bge-large-en-v1.5`** (1024 dim) — выше качество, медленнее, заметно толще индекс.
- **`bge-base-en-v1.5`** (768 dim) — близко к Nomic по качеству.
- **`text-embedding-3-small`** (1536 dim) от OpenAI — если не жалко денег и сети.

После смены модели **обязательно** `rm -rf .gofer/data/ && gofer reindex --force` — векторы прежней модели несовместимы.

### Я работаю над несколькими проектами одновременно. Что делать?

Демон один, проектов сколько угодно. В каждом каталоге:

```bash
cd /path/project-a && gofer init && gofer start
cd /path/project-b && gofer init && gofer start
```

`gofer status` покажет все активные. `gofer sleep` (внутри каталога проекта) деактивирует один, не трогая остальные. `gofer down` гасит демон со всеми проектами разом.

### Куда положить gofer в системе?

`cargo install --path . --locked` положит в `~/.cargo/bin/gofer`. Никаких дополнительных шагов нет: ни systemd-юнит, ни launchd, ни докер. Демон сам стартует по `gofer up` и сам демонизируется.

Если хочется автозапуск — добавь `gofer up` в shell-init или используй системный сервис-менеджер вручную.

### Где gofer хранит данные?

- Глобально: `~/.gofer/` (сокет, логи, реестр, скачанные грамматики).
- Per-project: `<project>/.gofer/data/` (индекс SQLite + векторы LanceDB).

Снести индекс одного проекта = удалить `<project>/.gofer/data/`. Снести всё = `rm -rf ~/.gofer/` + всё, что в проектах.

## Использование

### Можно ли использовать gofer без MCP-клиента?

Да — у gofer есть CLI:

```bash
gofer search "auth middleware"
gofer reindex
gofer status
```

Но полный набор инструментов (skeleton, read_function_context, batch, structural_search и т. д.) доступен только через MCP. CLI закрывает базовые сценарии.

### Можно ли вызывать gofer из скриптов?

Да — JSON-RPC поверх `~/.gofer/daemon.sock` стандартный:

```bash
echo '{"jsonrpc":"2.0","id":1,"method":"tools/call",
       "params":{"project_path":"'$PWD'","name":"search",
                 "arguments":{"query":"auth","limit":3}}}' | \
  nc -U ~/.gofer/daemon.sock
```

Любой клиент, говорящий JSON-RPC 2.0, подойдёт.

### Что считается «свежей» индексацией?

Файл считается актуальным, если `content_hash` (blake3) в SQLite совпадает с реальным содержимым. При запуске `gofer start` сравниваются хеши и переиндексируются только изменённые. Watcher делает то же реактивно — изменение → инкрементальная переиндексация.

«Полная переиндексация» (`gofer reindex --force`) сносит все хеши и пересчитывает всё с нуля.

### Можно ли индексировать репозиторий, который я не клонирую (просто .git без working tree)?

Нет. gofer работает с файлами на диске. Bare-репо требует checkout.

### А внешние deps? `~/.cargo/registry`?

По умолчанию **нет**. Игноры `.gitignore` + `[indexer].ignore` обычно отрезают `target/`, `node_modules/`, `venv/`. Если очень хочется заиндексировать чужой код — снимай игноры явно (но проиндексировать `cargo registry` целиком — плохая идея, размер индекса вырастет в 10×).

## Ассистент / LLM

### Какие токены экономит skeleton?

Типичный Rust-файл на 500 строк — ~6000 токенов. `skeleton` оставит ~1500–2000 (только сигнатуры, типы, docs). Экономия 3–4×.

`read_function_context` для одной функции внутри такого файла — обычно 500–800 токенов. Экономия 10×.

`read_types_only` для модуля моделей — может вырезать 95% объёма, если в файле много impl-блоков.

Подробные замеры — в `tests/*_comparison.md` (см. [tests/README.md](../tests/README.md)).

### Что делать, если поиск возвращает мусор?

См. [troubleshooting.md::`search` отдаёт ерунду](troubleshooting.md#search-отдаёт-ерунду--низкие-score). Самые частые причины: модель эмбеддера сменилась без переиндексации, низкий `min_score`, неподходящий запрос.

### Можно ли учить gofer на нашем коде?

gofer не учит — он индексирует. Учится эмбеддер, который вы используете. Можете подменить общую модель на дообученную под ваш домен — в `[embedding].external_url` укажите её endpoint.

`golden_samples` и `rules` — это **подсказки для ассистента**, не fine-tuning. Они идут в системный prompt через ресурс `project://context`.

## Ограничения

### Поддерживается Windows?

Не тестировалось. Демон использует Unix-сокет (`daemonize` crate). Под Windows нужно как минимум переписать IPC на named pipes — этого пока нет.

### Поддерживается работа без сети?

Если у тебя есть локальный HTTP-эмбеддер — да. lang-hub auto-download требует сети, но **только** при первой установке грамматики. После — индексация и поиск работают offline.

### Поддерживается работа без эмбеддера?

Частично. Без эмбеддера отвалится `search`, `search_by_purpose`, `smart_file_selection` (всё, что использует векторы). Работают: `grep`, `find_files`, `read_*`, `skeleton`, `get_symbols`, `get_callers`/`get_callees`, `structural_search`, git-инструменты.

### Что с private-keys и секретами в индексе?

gofer индексирует **все** файлы, не отфильтрованные `.gitignore` или `[indexer].ignore`. Если у тебя в репо лежит `.env` с реальными секретами — он попадёт в `index.sqlite` и `lance/`. Эмбеддинги текстов уйдут на эмбеддер. **Это твоя ответственность** — не индексировать секреты.

Стандартный приём: положи `.env*`, `secrets/`, `*.pem` в `.gitignore` или `[indexer].ignore`.

## Сообщество и поддержка

### Куда жаловаться?

Issue/PR — в репозиторий проекта (GitHub `pa-khan/gofer`). Перед issue — собери `gofer health`, `gofer status`, `gofer logs -n 200`, версию (`gofer --version`), описание сценария.

### Roadmap?

Часть планов — в `docs/archive/next_stage/IMPLEMENTATION_PLAN.md` (исторический документ). Активные направления: runtime-context (Phase 1), production-intel (Phase 2), security/multi-version (Phase 3+). Чёткой публичной roadmap нет, проект — pet-project одного автора.

### Как поучаствовать?

См. [CONTRIBUTING.md](../CONTRIBUTING.md). Если хочешь крупное изменение — лучше сначала issue с обсуждением, чтобы не перепиливать потом.
