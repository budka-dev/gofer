# Contributing to gofer

Спасибо за интерес. gofer — pet-проект одного автора (`pa-khan@`), и любая помощь ценна. Этот файл — короткий гайд для внешних контрибьюторов. Подробности про устройство проекта и рецепты — в [docs/development.md](docs/development.md).

## Прежде чем писать код

Если меняешь что-то существенное (новые инструменты, изменение API, миграции схемы) — открой issue до PR. Это сэкономит время: вдруг это направление уже обсуждалось или конфликтует с другой работой.

Мелкие правки (опечатки в доках, фикс комментария, очевидный баг) — сразу PR, обсудим там.

## Окружение разработки

Требования и инструкции по сборке/тестам — [docs/development.md](docs/development.md). Кратко:

```bash
cargo build
cargo test
cargo fmt --check
cargo clippy --all-targets -- -D warnings
```

Прежде чем коммитить — всё должно быть зелёным.

## Стиль коммитов

Conventional Commits приветствуются (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`), но не обязательны. Глядя на историю, видно, что строгого стиля нет — пиши осмысленные сообщения, и этого достаточно.

Один коммит = одно логическое изменение. Если в одном PR трогаешь несколько вещей, разнеси по коммитам.

## Pull request чек-лист

- [ ] `cargo fmt`, `cargo clippy`, `cargo test` зелёные.
- [ ] Новые миграции пронумерованы по порядку, не правят существующие.
- [ ] Новый MCP-инструмент: handler + `dispatch` + JSON-Schema + строка в [docs/tools-reference.md](docs/tools-reference.md).
- [ ] Новый CLI-флаг: обновлён README.
- [ ] Не закоммичен `.sqlx/` мусор и `target/`.
- [ ] Если ломаешь публичный API инструмента — отметь это в описании PR явно.
- [ ] Описание PR содержит: что меняется, зачем, как тестировал.

Шаги добавления нового инструмента и миграции — [docs/development.md::Добавление MCP-инструмента](docs/development.md#добавление-mcp-инструмента-рецепт).

## Что приветствуется

- Багфиксы с минимальным test case.
- Документация. Серьёзно — если что-то в docs неточное или непонятное, PR на правку всегда принимается.
- Новые языковые пакеты для [lang-hub](docs/lang-hub.md) — это отдельный репозиторий `budka-dev/lang-hub`.
- Новые MCP-инструменты с чётко обоснованным use case.
- Оптимизации с замерами (`tests/*_comparison.md`-стиль).

## Что обсуждается отдельно

- Изменение публичного API существующих инструментов.
- Альтернативные backends хранилища (вместо SQLite/LanceDB).
- Локальный эмбеддер (см. [docs/faq.md::Зачем внешний эмбеддер?](docs/faq.md#зачем-внешний-эмбеддер-не-проще-ли-локально)).
- Windows-поддержка — потребует переписать IPC.

## Кодекс взаимодействия

Будь конструктивен. Если что-то непонятно — спроси, не догадывайся. Если PR висит — пинг автору в issue или комментариях нормально.

## Лицензия

Контрибьюшен принимается под лицензией проекта (см. `LICENSE` в корне). Отдельных CLA нет.
